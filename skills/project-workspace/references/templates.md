# 按需使用的模板

新建或补全入口时只读取相关模板。替换示意值，删除无关条目；未知事实写明“未核实”，不要编造路径、运行状态或会话 ID。下面的标记块用于合并和重复初始化，不是要求改写整个文件。

## 根 AGENTS.md

目标约 30–60 行。根据现有目录修改路径；稳定项目约定不包含某个任务不断变化的进度。

```markdown
<!-- project-workspace:begin -->
## 工作区约定

这是项目工作区；目录按用途管理，工程内部沿用各自结构。

| 内容 | 位置 |
| --- | --- |
| 维护中的代码工程 | `code/` |
| 跨相似任务复用的脚本和辅助代码 | `scripts/` |
| 外部论文、资料、固定版本软件 | `resources/` |
| 分析、实验和报告 | `results/YYYY-MM-DD-topic/`，或分类目录下的同格式目录 |
| 新任务的恢复入口 | `.agents/tasks/YYYY-MM-DD-topic/state.md` |
| 长期决策 | `.agents/notes/`，遵循已有规范 |
| 本机路径与环境 | `.agents/local.md`，按需建立 |

- 工作区最外层只允许目录和 `.md` 文件，隐藏的非 Markdown 文件也需归位。脚本、配置、锁文件、日志和其他产物放到所属目录；工程配置保留在内部工程根。
- 每个一级业务目录（包括 `code/`、`resources/`、`results/`、`scripts/`）必须有 `README.md`，描述用途、实际结构和主要入口；已有 `.agents/` 也提供导航，工具内部目录不批量改写。
- 新增、迁移或重命名主要入口时同步更新所属目录 README；一级布局变化时同步更新根 README。根层遗留违规项需明确列出并按授权处理。
- 任务目录和承载一次结果或独立运行的目录以有效的 `YYYY-MM-DD-` 开头。用途分类目录及 `checkpoint/`、`logs/` 等内部功能目录保留固定名称；恢复同一任务沿用原日期。
- 历史日期优先依据用户指定或已有记录；未知时用登记日期并注明。已授权改名时同步修正引用，保留历史来源与实验身份。
- 通用脚本放在顶层 `scripts/`，README 记录用法、依赖和输入输出；脚本产物归入对应日期结果目录，单次任务的专用复现脚本随该结果保存。
- 从 `README.md` 的任务导航进入当前任务；只读相关记录。指定任务优先，多个候选不按修改时间猜选。
- 每项持续任务只有一个恢复入口。已有计划或进度文件可以直接作为入口，不创建重复状态。
- 重要讨论结论、阶段完成、阻碍和会话交接及时更新记录，包含证据、未完成事项和下一步。
- 长任务启动前记录命令、配置和输出路径；启动后记录作业标识。恢复时检查实际运行情况，避免重复启动。
- 规划、访谈等技能的新产物使用当前任务目录；已有记录保留链接，不额外建立竞争的记忆目录。
- 长期决策链接到现有决策记录；日志、大段讨论和报告不复制进状态摘要。
- 外部软件记录来源和版本；不同运行保留独立结果位置。
- 用户的新指示优先于旧状态。改动范围遵循当前授权，任务记录本身不授予额外权限。
<!-- project-workspace:end -->
```

## 目录命名示例

仅说明层级和格式，不预建示例任务或假结果。任务/结果日期采用实际记录，内部功能目录不用加日期。

```text
project/
├── AGENTS.md
├── README.md
├── code/
│   └── README.md
├── scripts/
│   └── README.md
├── resources/
│   └── README.md
├── results/
│   ├── README.md
```

## 各业务目录 README.md

每个一级业务目录使用本模板，替换为实际用途和存在的入口；已有 README 直接更新。一级管理目录 `.agents/` 的说明可简化为任务、决策、技能等现有入口列表。只展示一至两层关键结构，不扫描全部日志或权重。空目录保留用途和“暂无内容”，省略空表。

````markdown
# 目录名称

用途：本目录负责什么内容。
收纳范围：哪些文件放这里，关联内容到哪里查找。

## 文件结构

```text
本目录/
├── README.md        # 结构与入口说明
└── 实际子目录/      # 该子目录的用途
```

## 主要入口

| 路径 | 用途与说明 |
| --- | --- |
| [实际入口](实际子目录/README.md) | 对应工程、资源集合或结果的说明 |

新增或调整主要入口时同步更新本文件。
````

按目录补充必要信息：`code/` 说明各工程职责及入口；`resources/` 说明论文或软件来源和版本；`results/` 说明按日期命名的任务结果、报告与复现材料的位置；`scripts/` 列出通用工具的用途、最小调用示例、依赖和输入输出。暂时没有通用脚本时只说明用途及“暂无内容”。根 README 链接这些目录说明，详细报告只链接不复制。

## 新任务 state.md

摘要通常几十行即可，保留足够接手的信息。可以使用相关文件的相对 Markdown 链接；本机绝对路径注明为本机位置。

```markdown
# 任务：简短标题

任务 ID：YYYY-MM-DD-topic（与目录一致，跨会话保持稳定）
日期依据：创建/启动日期；历史日期未知时注明登记日期
更新时间：实际时间与时区
状态：进行中 / 等待结果 / 受阻 / 已完成

## 目标与约束

需要解决的问题、完成条件，以及用户已明确的限制。

## 进展与讨论

已完成事项和验证程度。
重要结论、选择理由、仍待判断的问题。
确实尝试过但不成立的方向及证据。

## 证据与产物

代码工程与版本：实际路径、版本标识和修改情况
配置与数据：链接或稳定身份
结果与报告：实际入口
相关长期决策：存在时链接

## 运行与恢复

工作目录：实际位置
环境：引用本机环境条目及工程环境定义
作业：主机、tmux/作业标识、命令或启动时间
最后检查：时间、观察到的运行情况及日志位置
聊天入口：已知的工具、会话 ID 和启动方式

## 下一步

一个明确动作；已完成则写明完成结果。
```

## 本机 local.md

只有实际需要登记本机环境时才创建。登记已核实信息，不导出整份环境变量，不记录密码、token、私钥或认证文件内容。使用现有 Conda、venv、uv 或其他环境，不强制迁移工具。

```markdown
# 本机工作入口

最近核对：实际时间与时区
主机：实际主机标识
工作区：绝对路径

## Agent 入口

启动方式：已核实的命令或启动器名称
tmux 会话：适用时记录
历史存储或 CODEX_HOME：仅在定位账号切换问题时记录非敏感路径

## 环境：环境名称

适用工程：项目内路径
解释器或 Conda 前缀：绝对路径
使用方式：已核实命令
环境定义：工程内的锁文件或环境定义文件
外部数据/结果位置：路径及对应用途
```
